<objective>
Add instant, client-side title search to the notes list (LIST-03). Users type in a
search box above the list and the visible notes narrow in real time to those whose
`title` contains the query (case-insensitive substring). Clearing the box restores the
full list. Titles are plaintext (not encrypted — see 02-03-SUMMARY residual note), so
the filter reads `note.title` directly with no decryption.

**Why one plan, not the two ROADMAP hints:** both hints ("search state + filter logic"
and "search UI") modify the SAME single file (`NotesTab.vue`) and are meaningless in
isolation — the `filteredNotes` computed is dead code without the `<InputText>` that
drives `searchQuery`, and the input has nothing to bind without the computed. Splitting
them would force a sequential 2-plan chain on one file with no parallelism benefit and
extra context overhead. Instead this plan uses two tightly-scoped tasks: Task 1 extracts
the filter as a pure, unit-tested helper; Task 2 wires state + UI into `NotesTab.vue`.

Purpose: satisfy LIST-03 — instant title filtering with no server round-trip.

Honest analysis: this feature adds no new backend input, no new network call, no new
persisted data, and no new sink. It filters an existing in-memory array by a plaintext
title substring. No new threats are introduced.
