| user input → note title | InputText, 500-char maxlength enforced client-side and by PocketBase schema |
| user input → note body | Tiptap editor, JSON serialised; no HTML stored |
| client → PocketBase write | pb.collection('kaheeta_notes').create/update — JWT in pb.authStore; collection rules enforce user = @request.auth.id server-side |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Spoofing / Elevation of Privilege | ManageNote saveFn create payload | mitigate | user field in create payload set to auth.user?.id (client-side); server rule `user = @request.auth.id` independently enforces ownership — client cannot forge a different user ID |
| T-03-02 | Info Disclosure | notes list filter | mitigate | instrumentedGetFullList called with filter `user = '${auth.user?.id ?? ''}'` AND collection rule `user = @request.auth.id`; defence-in-depth — both client filter and server rule must pass |
| T-03-03 | Tampering | delete confirmation | mitigate | useConfirm().require() provides a two-step confirmation before pb.collection('kaheeta_notes').delete(); prevents accidental or CSRF-style deletions from a button tap |
| T-03-04 | Denial of Service | auto-save frequency | accept | 1000ms debounce + flush-on-close limits PocketBase write rate to at most 1/s per note session; no further throttling needed for a personal app |
