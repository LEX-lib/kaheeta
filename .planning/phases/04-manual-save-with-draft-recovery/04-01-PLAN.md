<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| app memory → localStorage (device disk) | Note content (title + body) is now persisted to the browser's localStorage as a draft. This is the one new data-at-rest surface this phase introduces. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Information Disclosure | draft written to localStorage (`noteDraft.saveDraft`) | mitigate | Encrypt the `{title, body}` blob with the SAME AES-GCM key path as saved notes (`encryptBody` from notesCrypto) before writing (D-02). No plaintext note content touches disk. Enforced by a Task-1 acceptance criterion that asserts the raw stored value contains no plaintext title/body. |
| T-04-02 | Tampering | corrupt/forged localStorage draft value | mitigate | `loadDraft` guards `JSON.parse` and `decryptBody` in try/catch, returns null on ANY error (never crashes, never trusts a bad blob). AES-GCM's auth tag causes `decryptBody` to reject a tampered ciphertext, which `loadDraft` treats as "no draft". |
| T-04-03 | Information Disclosure | XSS reading localStorage | accept | Residual, not new: the draft is ciphertext (T-04-01), and the app already stores the auth token in localStorage via `pb.authStore`. This introduces no new class of exposure and no new plaintext sink. |
</threat_model>
