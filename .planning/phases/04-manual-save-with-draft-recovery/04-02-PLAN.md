## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-04 | Information Disclosure | draft write from ManageNote edit handlers | mitigate | Draft writes go through `noteDraft.saveDraft`, which encrypts with the shared AES-GCM key (D-02, enforced + tested in Plan 01). ManageNote passes the `getOrDeriveKey()` key — no plaintext content reaches disk. |
| T-04-05 | Information Disclosure | stale draft after delete | mitigate | `NotesTab.requestDelete` calls `clearDraft(note.id)` on successful delete so content for a removed note does not linger in localStorage. |
| T-04-06 | Tampering / Repudiation | recovery prompt swapping content silently | mitigate | D-03 requires an explicit Restore/Discard confirm before any draft content replaces the saved content — no silent swap. `loadDraft` returns null on a tampered/corrupt draft (AES-GCM auth tag), so the prompt is skipped rather than restoring garbage. |
| T-04-07 | Information Disclosure | XSS reading localStorage draft | accept | Residual, not new: draft is ciphertext (T-04-04); auth token already lives in localStorage via `pb.authStore`. No new class of exposure, no new plaintext sink, no new network call. |
</threat_model>
