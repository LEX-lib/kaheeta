<objective>
Build the session key lifecycle: a `useNotesCrypto` composable that bootstraps a per-user salt in a new `kaheeta_user_settings` PocketBase collection, derives the AES-GCM key once per session via the Plan 01 primitive, caches it in a module-scoped variable, and clears it on logout. Delivers ENC-02 (transparent key derivation from the user session, no second password).

Purpose: Plan 01 gave us stateless primitives. This plan owns the *stateful* concerns — where the salt lives, when PBKDF2 runs, and how the derived key is cached and invalidated. Plan 03 consumes `getOrDeriveKey()` from both the editor and the list.

Output: `useNotesCrypto.ts` composable and a `UserSettings` type added to the notes types file. Requires a one-time operator setup of the `kaheeta_user_settings` collection (documented as user_setup).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → PocketBase (kaheeta_user_settings) | Salt read/write must be scoped to the authenticated user only |
| session memory | Derived CryptoKey lives in module memory; must not leak across users on a shared browser |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-05 | Elevation of Privilege | kaheeta_user_settings write | mitigate | Collection rules `user = @request.auth.id` (setup task) prevent writing another user's salt record (RESEARCH V4). |
| T-02-06 | Information Disclosure | cached key on shared device | mitigate | pb.authStore.onChange clears cachedKey when record becomes null (Pitfall 3, D-01). |
| T-02-07 | Cryptographic weakness / data loss | key material choice | mitigate | Key material is auto.user.id (immutable PK), NEVER token (D-01). Acceptance criteria greps for absence of `.token`. |
| T-02-08 | Repudiation / integrity | salt persistence race | accept | First-write may double-create only if two tabs bootstrap simultaneously; unique constraint on `user` field (setup task) causes the second create to fail and fall back to read. Low risk for a single-user personal app. |
| T-02-SC | Tampering | npm installs | mitigate | No packages installed (D-02). No install task exists. |
</threat_model>
