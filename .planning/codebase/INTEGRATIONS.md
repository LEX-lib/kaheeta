# Integrations

**Analysis Date:** 2026-06-30

## External Services

**Iconify CDN:**
- Runtime icon fetching from the Iconify API for any MDI icon not bundled in `src/lib/mdi-icons.json`
- Icons used in-app are pre-bundled locally to avoid CDN dependency on cold loads
- No API key required; public CDN

**No other third-party SaaS APIs detected** — the application is self-contained beyond PocketBase and the Iconify icon CDN.

## Authentication

**Provider:** PocketBase built-in auth (`pb.collection('users').authWithPassword`)

**Strategy:**
- Email + password authentication only (`src/stores/auth.ts`, `src/lib/pocketbase/index.ts`)
- JWT-based sessions managed by PocketBase SDK's `pb.authStore`
- Token validity checked on every navigation in `src/router/index.ts` (`beforeEach` guard)
- 401 responses automatically clear the auth store via `pb.afterSend` hook in `src/lib/pocketbase/index.ts`
- Session persisted in PocketBase SDK's default storage (localStorage-backed)
- No OAuth, no magic links, no third-party SSO detected
- Signup flow is commented out in `src/stores/auth.ts` — user accounts are created out-of-band

**Auth guard:**
- Routes with `meta.requiresAuth: true` redirect to `/login?redirect=<original-path>` when unauthenticated
- Only `/wallet` is auth-protected; `/` (landing) and `/login` are public

## Database / Storage

**Backend BaaS:**
- PocketBase `^0.27.0` (`pocketbase` npm package)
- Self-hosted at `https://api.delveen.cc` (production); CORS is wildcard, no origin allowlisting needed
- Singleton client: `src/lib/pocketbase/index.ts` exports `pb`
- All reads use `instrumentedGetFullList<T>(collection, options)` from `src/lib/pocketbase/perfInstrument.ts` — never call `pb.collection().getFullList()` directly from components

**Collections (PocketBase tables):**
- `wallecx_vaccinations` — vaccination records (legacy prefix, do not rename)
- `wallecx_memberships` — membership cards (legacy prefix, do not rename)
- `wallecx_expenses` — expense entries (legacy prefix, do not rename)
- `wallecx_expense_categories` — expense categories (legacy prefix, do not rename)
- `wallecx_expense_budgets` — budget entries (legacy prefix, do not rename)
- `kaheeta_*` — new collections use the `kaheeta_` prefix
- `users` — built-in PocketBase users collection

**Write mappers** (strip typed records to writable fields before create/update):
- `src/lib/pocketbase/vaccinationMapper.ts`
- `src/lib/pocketbase/membershipMapper.ts`
- `src/lib/pocketbase/expenseMapper.ts`
- `src/lib/pocketbase/expenseBudgetMapper.ts`
- `src/lib/pocketbase/checklistMapper.ts`
- `src/lib/pocketbase/checklistTaskMapper.ts`

**Server-side hooks:**
- `pocketbase/pb_hooks/kaheeta_splits.pb.js` — PocketBase goja hooks for splits feature; runs on the PocketBase server (not Node); plain ES5-compatible JS (no modules, no `const` at module scope)

**File/Image Storage:**
- PocketBase handles file uploads (images for vaccinations/memberships)
- Client-side compression via `browser-image-compression ^2.0.2` before upload (`src/lib/wallecx/compressToWebP.ts`)

**Local Storage (browser):**
- `kaheeta:theme` — dark/light mode preference
- `kaheeta:perf-baseline` — rolling window of last 5 perf samples per collection
- `kaheeta:perf-session:<collection>` — sessionStorage flag to log once per session
- `kaheeta:view-mode` and other UI state keys (prefix `kaheeta:`)

**ORM / Query layer:** None — direct PocketBase SDK calls with TypeScript generics. Types defined in `src/types/wallecx/<feature>/types.d.ts`.

## Deployment & Infrastructure

**Hosting (frontend):**
- Static SPA deployed as a PWA — production build output to `dist/`
- Served as static files; `navigateFallback: 'index.html'` for client-side routing
- No containerization config detected (no Dockerfile, no docker-compose)

**Hosting (backend):**
- PocketBase self-hosted at `https://api.delveen.cc`
- Shared backend with the origin project (Wallecx/Delveen)

**CI/CD:**
- No CI/CD pipeline detected (no `.github/workflows/`, no GitLab CI, no CircleCI config)
- Build is manual: `npm run build` → produces `dist/`

**PWA delivery:**
- Service worker generated by Workbox `generateSW` strategy
- `registerType: 'prompt'` — user must accept updates; never auto-updates (CRUD forms may have unsaved state)
- SW caches: `**/*.{js,css,html,ico,png,svg,woff2,webmanifest}`, max 3 MB per asset
- API requests (`/api/*`) bypass the SW (`NetworkOnly` handler)
- iOS localStorage eviction mitigation in `WallecxApp.vue` `onMounted`: re-checks `pb.authStore.isValid`, calls `navigator.storage.persist()`

**Environment configuration:**
- `VITE_API_BASE_URL` — required; points at PocketBase backend
  - Development default: set in `.env.development` (gitignored base `.env` holds local overrides)
  - Production: `https://api.delveen.cc` (`.env.production`)
- `BASE_URL` — Vite built-in, used in router `createWebHistory`
